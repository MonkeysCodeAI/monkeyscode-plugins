# PostgreSQL structured read-only connector

This first-party, dependency-free Node stdio MCP server uses a separately installed, reviewed local `psql`. It is **disabled by default**. Nothing connects at installation. It implements protocol versions 2024-11-05 and 2025-03-26, with only `list_tables`, `describe_table`, and `sample_rows`. There is no arbitrary SQL tool, SQL regex safety classifier, shell execution, or supplied driver binary.

## Operator configuration

Review the local psql distribution, version, provenance and license independently. Set `MONKEYSCODE_PSQL_PATH` to its absolute executable path and `MONKEYSCODE_PSQL_SHA256` to the reviewed binary's SHA-256. The server verifies that digest and rejects group/world-writable binaries and resolved ancestor directories. This digest is an operator trust anchor, not a vendor signature or library verification; protect the binary, directories and linked dependencies from replacement. Re-review upgrades and update the digest deliberately.

Supply explicit `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER` and either `PGPASSFILE` (preferred, locally protected) or `PGPASSWORD` in the user environment. Supply `PGSSLROOTCERT` as appropriate. TLS is forced to `verify-full`; insecure downgrade options are not inherited. Host/database are operator-selected, never tool arguments. `PGUSER` must be a lowercase identifier of at most 63 characters. Resolve the `.mcp.json` environment references in your host and enable the server only after review. Never commit credentials or include them in diagnostic reports.

Use a dedicated non-owner, non-superuser database role with only required SELECT grants. Revoke database TEMP and CREATE, schema CREATE, table/column mutation privileges and sequence USAGE/UPDATE, including inherited/PUBLIC grants. The guard rejects CREATEDB, CREATEROLE, REPLICATION and BYPASSRLS roles as well. Standard PUBLIC TEMP defaults can therefore cause rejection until explicitly revoked. The exact effective role and effective privileges are checked on every call, inside the same read-only transaction used for inspection.

## Boundaries

Schema inputs are restricted to `public` and `pg_catalog`; sampling is public-only. Table names accept only `[a-z_][a-z0-9_]{0,62}` and are quoted in fixed templates. Lists/metadata are capped at 100 entries; samples default to 10 and cannot exceed 100. Samples reject views, foreign/partitioned tables, RLS and custom column types, and use ONLY to exclude inheritance children. No caller-supplied expression, function, column list or SQL is executed. Built-in catalog queries and JSON conversion still execute database code: this is not a sandbox against a malicious administrator, tampered catalogs/extensions or compromised PostgreSQL installation. Selected data may itself be sensitive; authorize SELECT appropriately. Transaction read-only alone is not a guarantee against volatile functions or external effects.

psql ignores startup files, never prompts, receives only an explicit libpq environment, and has hardcoded read-only/5-second statement and idle-transaction/1-second lock settings. Each subprocess has a 6-second deadline and a combined 64-KiB output budget. Raw database stderr and credentials are never returned. Transport is newline-delimited JSON, with an 8-KiB input bound and one outstanding message at a time; pipelining is rejected. Missing/unverified configuration exits with a redacted stderr diagnostic rather than advertising an unavailable connection as operational.

## Verification status

The default test fixture exercises structured argument rejection, fixed SQL guards and injected execution responses without connecting to a database. An optional real-PostgreSQL test runs only with `MARKETPLACE_PG_TEST_REQUIRED=1`; otherwise that test is explicitly skipped. When requested, missing configuration or connection/setup failures fail the test rather than skip. Supply `MARKETPLACE_PG_TEST_ADMIN_DSN` as a PostgreSQL URI with explicit `127.0.0.1` host, numeric port, database and admin username (no query options), and `FIRST_PARTY_TEST_PSQL_PATH` as an absolute approved executable path. Keep the DSN out of logs and source control. The admin must be able to create/drop databases and login roles (PostgreSQL 13+ for DROP DATABASE FORCE). The test creates random, isolated database/role names, seeds tables/view/RLS/function fixtures, revokes PUBLIC CREATE/TEMP only in that new database, verifies structured reads and rejected writes/admin/view/RLS/injection/global-write/PUBLIC-TEMP grants, and cleans up only successfully created names in finally. It never changes grants in the provided admin database. Local test connections deliberately disable TLS; the test computes the exact supplied binary digest and retains production permission checks, while production configuration still forces verify-full and independently reviewed digests. This opt-in test does **not** establish production database enforcement or certificate validation, and no live run is claimed by its inclusion. Before enabling, the operator must test an isolated PostgreSQL instance: accepted dedicated read role; rejected owner/admin/inherited write roles; CREATE/TEMP and column/sequence grants; views, RLS, custom types, identifier injection, output overflow and timeouts; certificate failures and role mismatch. Protect schema DDL from untrusted concurrent changes. No live-database acceptance or cloud deployment is claimed here. The included review skill remains available independently.
